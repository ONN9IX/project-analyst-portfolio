# Методика расчёта и границы данных

## Происхождение

Данные из публичного REST API `GET /repos/ONN9IX/smart-garden/issues?state=all` и `GET /repos/ONN9IX/smart-garden/pulls?state=all`. Выгрузка зафиксирована 13.10.2026. Для Issues из общего GitHub endpoint исключены объекты, содержащие `pull_request`, чтобы не считать PR как задачи повторно.

В компактном seed на дату проверки сохранены подтверждённые идентификаторы, статусы и календарные даты; полные описания доступны через индивидуальные URL, названия в CSV заполнены только для выбранных проверенных Issues. `refresh_from_github.py` создаёт полную актуальную выгрузку для повторного анализа.

## Определения

- `issues_total = COUNT(Issues)`; `closed = COUNT(state == closed)`; `open = COUNT(state == open)`.
- `closed_share = issues_closed / issues_total`. **Не** процент завершённости продукта.
- `prs_merged = COUNT(merged_at IS NOT NULL)`; остальные PR разделяются на `open` и `closed_not_merged`.
- `daily_activity` — число созданных/закрытых Issues и созданных/объединённых PR **по календарным дням**.
- `assignee` — назначенный участник GitHub; пустое значение означает отсутствие assignee, а не отсутствие фактического исполнителя.

## Не вычисляем без данных

- Сроки по плану, календарное отклонение, критический путь, burndown относительно baseline.
- Трудозатраты, часовую производительность, реальный lead/cycle time с точностью до часов.
- Бюджет, CPI/SPI, EV, PV, AC, стоимость проекта.
- Количество людей в команде по assignee: назначение задачи не доказывает состав команды.

## Возможные искажения

- Issue может закрываться по причинам, не связанным с завершением разработки.
- GitHub даты изменения задач не равны времени работы над ними.
- Одна крупная Issue и одна маленькая Issue имеют одинаковый вес в простом счётчике.
- Историческая задача может быть закрыта, а продуктовый функционал оставлен выключенным.
- 13.10.2026 — дата среза, более поздние события не представлены.

## Результаты проверки

`python -m unittest discover -s tests -v` сверяет длины, статусы, ссылки и уникальные идентификаторы. Числа в отчётах берутся из CSV, а не прописываются в аналитическом коде вручную.
