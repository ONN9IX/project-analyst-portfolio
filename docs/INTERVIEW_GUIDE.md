# Interview guide — Junior Project Analyst / PMO Analyst

## 60-секундный рассказ о кейсе

«У меня есть собственный учебно-практический IT-проект ПРОМАКС. Для демонстрации навыков аналитика проектов я отдельно исследовал его историю GitHub: собрал Issues и Pull Requests, разделил эти сущности, проверил уникальность и даты, сделал Excel-дашборд и SQL-отчёты. В срезе на 13 октября 2026 года — 137 Issues и 95 PR. Закрыты 118 Issues, объединены 88 PR. Я специально не называю 86,1% закрытых Issues процентом готовности продукта: задачи имеют разный вес, а в GitHub нет полной плановой базы. Поэтому сделал status report, реестр рисков и предложения по улучшению проектной отчётности».

**Рассказывай только о тех действиях, которые изучил и сможешь повторить.** Наличие файла не доказывает личную самостоятельность; перед собеседованием разберись в каждом расчёте.

## 12 вопросов, которые стоит знать

1. **Что делает Project Analyst?** Следит за данными о ходе работ, качеством статусов, рисками и отчётностью для управленческих решений.
2. **Чем Issue отличается от Pull Request?** Issue описывает задачу/обсуждение, PR предлагает изменение кода. В GitHub endpoint `/issues` PR тоже присутствуют, поэтому их исключили.
3. **Почему 118/137 ≠ 86,1% готовности?** Задачи разных размеров; закрытие может означать отмену/обход/дизайн, не фактическую поставку ценности.
4. **Что такое WBS?** Иерархическая декомпозиция объёма работ/результатов на управляемые компоненты.
5. **Что такое RACI?** Матрица, кто выполняет (R), отвечает за итог (A), консультирует (C) и информируется (I).
6. **Как считаешь риск?** В учебной матрице probability × impact. Это экспертная приоритизация, не объективная вероятность ущерба.
7. **Что такое baseline?** Зафиксированные и согласованные плановые сроки/объём/стоимость, относительно которых считаются отклонения.
8. **Какие нужны данные для план-факт?** Плановые и фактические даты/затраты, оценки объёма, правила определения готовности.
9. **Что такое EV/PV/AC?** Earned Value, Planned Value и Actual Cost. Без этих полей нельзя честно считать SPI=EV/PV и CPI=EV/AC.
10. **Как сформировал статусный отчёт?** Зафиксировал дату и источник, исключил PR из Issues, посчитал абсолютные количества и доли, выделил открытые риски, ограничил интерпретацию.
11. **Как использовал SQL?** Агрегация по статусам, window share, отдельные CTE для daily events и JOIN только уже агрегированных временных рядов во избежание размножения строк.
12. **Как поступишь, если менеджер просит срок, но baseline нет?** Сначала уточню scope, оценки, ответственных и зависимости, согласую baseline; непроверенный срок обозначу как предварительную гипотезу, а не факт.

## Мини-практика на 30 минут

- Открой Excel и сам найди формулу доли закрытых Issues (`B7/B6`).
- Напиши в SQL из головы `GROUP BY state`, затем поясни `COUNTIF` на том же примере.
- Объясни по одной открытой Issue #223 или #187: факт, риск и предлагаемая следующая проверка.
- Назови минимум три ограничения GitHub как источника план-факт.
- Покажи разницу «код слит» и «функция готова к пилоту».

## Нельзя говорить на собеседовании

- «Я работал больше года аналитиком в компании X», если такой работы не было.
- «Проект готов на 86,1%».
- «Потратил N рублей / часов», если нет учётных данных.
- «Готов для реальных персональных данных», если privacy/пилот не согласованы.
- «Я лично написал 88 PR», если метрика относится ко всему репозиторию.
